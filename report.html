1. Problem Statement & Motivation

When flatmates share apartment expenses or groups travel on vacations, managing shared finances inevitably creates a complex, tangled web of mutual obligations. Existing simple spreadsheet or basic CRUD applications fall short in three fundamental areas:

  • Circular Debt Inefficiencies: If Member A owes Member B ₹1,000, Member B owes Member C ₹800, and Member C owes Member A ₹600, traditional systems prompt 3 separate bank payments instead of collapsing the debt network to a single net transfer.
  • Penny & Remainder Inaccuracies: Splitting arbitrary bills (e.g. ₹100 split 3 ways) creates non-terminating decimals (₹33.333...), leading to accumulated fractional errors where splits fail to sum strictly to the receipt total.
  • Absence of Natural Business Guards: CRUD systems allow deleting records indiscriminately or removing members who still owe money, breaking ledger integrity.

EquiSplit solves these challenges by combining a custom mathematical split engine with the Min-Cash-Flow Greedy Algorithm, guaranteeing accurate ledgers and minimal payment transactions.

3. Core Engineering Logic & Mathematical Models

3.1. Min-Cash-Flow Greedy Debt Simplification Algorithm

Given a group of $N$ members with arbitrary shared transactions, the algorithm computes the net balance of each participant and simplifies the debt network to at most $(N - 1)$ transfers in $O(N \log N)$ time:

NetBalance(i) = [TotalPaid(i) + SettlementsSent(i)] - [TotalShare(i) + SettlementsReceived(i)]
  1. Members with NetBalance < -0.01 are classified as Debtors.
  2. Members with NetBalance > +0.01 are classified as Creditors.
  3. In each step, match the maximum debtor $D$ with the maximum creditor $C$:
    TransferAmount = min(|D.debt|, C.credit)
  4. Record payment $D \rightarrow C$, update remaining balances, and repeat until all balances are settled.

3.2. Penny-Accurate Multi-Split Math Engine

EquiSplit guarantees that $\sum \text{Splits} = \text{TotalAmount}$ strictly to 2 decimal places across all 4 split modes:

  • Equal Split: Divides total amount in cents/paise. Calculates base share and assigns 1 remainder cent to the first $R$ members ($R = \text{TotalCents} \pmod N$). Zero penny leaks.
  • Exact Amounts: Live verification that $\sum \text{ExactShares} = \text{TotalAmount}$; blocks submission if mismatched.
  • Percentages: Validates $\sum \text{Percentages} = 100\%$, allocating shares and adjusting fractional cents on the largest percentage share.
  • Weighted Shares: Proportionally calculates based on assigned weights (e.g., 2 shares for couples, 1 for singles).

4. Core Workflows Implemented

Workflow 1: Group Creation & 6-Character Invite Codes

Users create trip or flatmate groups with custom currencies. Each group automatically receives a unique 6-character uppercase invite code (e.g., GOA202) and a shareable link. Authorization ensures members only access their own groups.

Workflow 2: Precision Expense Creation & Multi-Payers

Supports both single-payer and multi-payer scenarios (e.g., Rahul paid ₹3,000 and Neha paid ₹3,000 on a ₹6,000 bill). The UI provides real-time validation warnings showing remaining unallocated amounts.

Workflow 3: One-Click Settle-Up & Live Debt Graph

Users can click "Settle" directly from any simplified debt card. Recording the settlement logs the transaction, updates member balances, updates the simplified transfer graph, and triggers celebratory confetti.

Workflow 4: Natural Safety Guards & Business Logic

Attempting to remove a member with an unsettled balance is blocked by API validation with an informative error message: "Cannot remove member! This user still owes ₹1,200.00. Please settle all balances first."

Workflow 5: Visual Analytics & Immutable Audit Trail

Interactive category spending breakdown with progress bars, comparative Paid vs. Consumed metrics, and an audit trail recording all expense creations, edits, deletions, and settlements.
